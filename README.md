## 🏛️ About Me

I am a **Systems Engineering student at Pontificia Universidad Javeriana**, based in Bogotá, Colombia, focused on backend engineering, software architecture, relational data integrity, automated testing, and cloud deployment.

My engineering interests revolve around designing software that is not only functional but also maintainable, secure, testable, and capable of evolving alongside its requirements.

I enjoy transforming complex problems into structured software solutions through architectural reasoning, modular implementation, and evidence-based technical decisions.

In November 2026, my team and I completed the academic milestone for **CareStock**, a multi-pharmacy inventory management system built with Java 21, JavaFX, and PostgreSQL.

I am currently developing **CORPUS**, a client-oriented bilingual environmental terminology platform whose first functional web prototype was deployed to the cloud and delivered to the client on November 26, 2026.

I also developed **VerbQuest**, an educational web application combining adaptive learning, gamification, and real-time multiplayer competitions.

I integrate artificial intelligence as an engineering copilot to accelerate prototyping, research, documentation, and technical analysis while maintaining human review, empirical verification, and ownership of architectural decisions.

CareStock is a team-engineered desktop application designed to manage inventory across multiple pharmacies, providing tenant-scoped data segregation, role-based access, product catalog management, and lot-level traceability.

The system was developed as an academic software engineering project with an emphasis on architectural consistency, automated quality assurance, and reproducible delivery.

### Core Capabilities

- Multi-pharmacy inventory management.
- Pharmacy-scoped data segregation.
- Role-based authentication and authorization.
- Active and inactive user management.
- Session lifecycle management and inactivity timeout.
- BCrypt password hashing.
- Product catalog management.
- Batch and lot traceability.
- Stock entry and withdrawal validation.
- Inventory movements.
- Pharmacy-specific indicators.
- Unified CRUD operations.
- Secure logout and session cleanup.

### Software Architecture

CareStock follows a layered MVC-oriented architecture within a standalone Java desktop process.

Design patterns applied throughout the system include:

| Pattern | Responsibility |
| :--- | :--- |
| MVC | Separation of presentation, application control and domain logic |
| Facade | Simplified access to complex inventory operations |
| Proxy | Controlled and cached inventory queries |
| Builder | Structured construction of domain objects |
| Singleton | Controlled session lifecycle and shared session state |

### Technical Highlights

- Java 21 and JavaFX 21.
- PostgreSQL 16 hosted through Neon.
- JDBC persistence with HikariCP connection pooling.
- Transactional inventory operations.
- Cached inventory queries with configurable TTL.
- Tenant-scoped query boundaries.
- UML class diagrams and C4 architecture documentation.
- Automated testing with JUnit 5 and Mockito.
- Coverage reports generated with JaCoCo.
- Static analysis and custom Java AST metrics.
- GitHub Actions quality pipelines.
- Isolated PostgreSQL integration tests.
- Docker container validation.
- Telegram build notifications.

### Applied Natural Language Processing

CORPUS integrates the Helsinki-NLP OPUS-MT Spanish-to-English neural translation model based on MarianMT.

The translation architecture includes:

- Local CPU-based neural inference.
- Batched translation.
- LRU caching.
- Concurrent access control.
- Duplicate translation avoidance.
- Configurable model warmup.
- Basic translation output quality checks.
- Persistent English definitions.
- Traceability of automatically generated definitions.

The persistent translation increment is designed to eliminate mandatory neural inference from ordinary cloud search requests.

Instead of loading the model for every definition lookup, translations can be generated in an authorized local environment, stored in PostgreSQL, and retrieved by the deployed application.

This architecture is particularly useful for resource-constrained hosting environments.

Machine-generated definitions remain subject to specialized linguistic and scientific review.
